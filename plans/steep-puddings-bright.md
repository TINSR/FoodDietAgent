# 算法层改进计划

## 背景

当前推荐算法存在以下问题：
1. **餐次推断简单** — 只检查是否有食物，未考虑时间和实际情况
2. **营养均衡缺失** — 只按热量匹配，未验证每餐蛋白质 ≥15g
3. **多样性不足** — 同类食物可能重复推荐
4. **宏量缺口未利用** — 未根据用户蛋白质/碳水/脂肪的实际缺口优先推荐

## 改进方案

### 1. 改进餐次推断 — `MealTypeInferer.java`

```java
public class MealTypeInferer {
    // 根据时间 + 已记录情况推断下一餐
    // 规则：
    // - 6:00-9:59 → 优先早餐（若未记录）
    // - 11:00-13:59 → 优先午餐
    // - 17:00-20:59 → 优先晚餐
    // - 其他时间 → 加餐
    // 已有食物的餐不再推荐
}
```

### 2. 增强食谱匹配评分 — `RecipeScoringService.java`

评分公式：
```
总分 = 热量匹配分 × 0.4 + 蛋白质缺口分 × 0.3 + 多样性分 × 0.2 + 目标匹配分 × 0.1
```

- **热量匹配分**：120 - |食谱热量 - 剩余热量|，最低 0
- **蛋白质缺口分**：若蛋白质进度 < 70%，优先推荐高蛋白食谱
- **多样性分**：避免与今日已推荐同分类食物（如今天已推荐鸡胸，不再重复推荐）
- **目标匹配分**：减肥用户推荐低脂，维持用户推荐均衡，增肌用户推荐高碳水

### 3. 新增营养均衡验证

`RecipeService.findMatchingRecipes()` 增加验证：
- 每餐必须含 ≥15g 蛋白质（防止只吃碳水）
- 脂肪占比不超过 35%
- 优先选择蛋白质密度 > 30% 的食谱

### 4. 新增宏量缺口推荐逻辑

根据用户宏量进度调整推荐：
- 蛋白质进度 < 50% → 优先推荐高蛋白食物（鱼、鸡胸、豆制品）
- 碳水进度 < 50% → 优先推荐高碳水食物（米饭、面条、土豆）
- 脂肪进度 > 80% → 避免高脂食物（肥肉、油炸）

## 验证方案

1. 启动应用
2. 调用 `/api/agent/analyze` 时观察推荐逻辑：
   - 蛋白质缺口大时是否优先推荐高蛋白食谱
   - 同一餐不会重复推荐同类食物
3. 检查返回的 `recipes` 列表是否包含营养均衡的食物
